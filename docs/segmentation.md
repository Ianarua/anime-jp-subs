# 断句算法：怎么把 Whisper 的词拼成"一行一句"

这份文档解释 `pipeline.py` 里 `segment_lines()` 那一整套为什么这么写。**结论都带实测数据**，
数字都是拿真实片源跑出来的；想改参数或换做法之前，先看这里有没有踩过。

---

## 1. 为什么不用中文字幕轨断句（曾经的做法，已废弃）

最初的做法是"照着中文字幕轨切"——把 Whisper 的每个词按时间归到它落在的那条中文台词上。
理由是"中文翻译的断句最接近播出节奏"。

**实测结果（6 集 / 4 部番）**：漏句 13~20%、语速异常 12~26%、等分痕迹 24~52 处。

| 指标 | 整段吸附（更早的版本） | 词级切分（后来的修补） |
|---|---|---|
| 漏句 | 42 处 | 1 处 |
| 语速异常 | 38 条 | 2 条 |
| 等分痕迹 | 33 处 | 0 处 |
| 语音覆盖率 | 74.5% | 81.7% |

但**根本问题没解决**：中文是翻译，它的断句是**翻译的断点**，不是日语的断点。照它切会把日语切在
半个词、行首助詞、感動詞跨行这些地方——一集能挑出几十处，而且越修越说明基准选错了
（为此加过三条修补规则：词被切两半就挪回下一句、感動詞挪到下一句、下一行以助詞开头就把上一条
末尾的词挪过去）。

**改成的做法**：不看中文轨，**听日语自己的换气**。中文轨现在只用来做"这集有没有中文字幕"的
存在性判断（片源要求），默认 `[align] mode = jp`；老路径 `align_timeline()` 整套保留，
`mode = cn` 才走。

## 2. 算法四步

### 第 1 步：silero VAD 找停顿（`detect_pauses`）

在 16kHz 单声道音频上跑 silero VAD：`threshold=0.5`、`min_silence_duration_ms=150`、
`speech_pad_ms=0`，得到**语音段**（字幕什么时候出现/消失的骨架）和**停顿**（在哪儿断行的候选）。

> ⚠ 这跟听写时用的那套 VAD 参数**不是一回事**：听写用的是 `VAD_PARAMS`
> （`min_silence_duration_ms=250`、`speech_pad_ms=50`），用途是决定 Whisper 在哪儿切块。
> 两处别混。

### 第 2 步：把 Whisper 的"段"贴回真实时间（`_segment_ranges`）

Whisper 的**句子切分可信、时间不可信**：

| 现象 | 实测 |
|---|---|
| 段边界离真停顿的距离 | 中位 0.21s（80% ≤0.3s、98% ≤0.6s） |
| 段首词被拉到段边界上 | 「俺」差 0.5s、「タ」差 4.2s |

所以做法是：把每个段的起止**吸附到最近的停顿**上（`SNAP_TOL=0.6s`，停顿起点 = 上一句结束、
终点 = 下一句开始）；附近没有停顿就保持原样。吸附后还要夹一次"起点不回退、结束不早于开始"
——两条边界吸到同一条停顿上时中间那段会被挤成 0 长度（实测不夹会出 21 行负时长，最夸张 -17.8s）。

### 第 3 步：词整块落在语音片上（`_retime_words` + `_group_words_to_slices`）

**这是 2026-09 最大的一次重做。** 老做法把每个词的时长按比例摊到整段语音上，于是语音之间的
**停顿会落在某个词的内部**：

> 实测「窓際のテーブルね」+ 0.67s 停顿 +「それは私が持っていくから」——停顿正好落在
> 「それは」**这个词里面**。用户想在这儿断开，可词表里根本没有这个缝；反过来，不该断的词缝上
> 又会因为"按 Whisper 段界注册切点"冒出假切点，于是断在句子中间（一集 23 处）。

现在：每个 Whisper 段里的词，按"哪几个词归哪一片 VAD 语音"做一次 DP 分组
（代价 = Σ|这组分到的词时长 − 这片语音应有的词时长|），片内再按词时长铺满 →
**停顿一定落在词与词之间**。拉伸比例整体夹在 0.75~1.6（段里混音乐时不许把 16 个字显示成 8 秒）。

布局窗口 = "吸附后的段范围 ∪ Whisper 自己的词时间范围"，但**不许退到上一段说过话的地方**
（否则会把词甩到别的语音片里，实测「ですか」被拆成 です|か）。

### 第 4 步：动态规划拼行（`segment_lines`）

**宽度是硬约束**：一行必须 ≤ 画面宽 80%（按字体真实字宽算，见 `furigana.text_em`），
因为注音层要求"一条字幕永远单行"。除此之外全是代价项，越小越该这么切：

| 代价项 | 值 | 为什么 |
|---|---|---|
| 强停顿（≥0.30s） | **−1.5** | 真换气，就该在这儿断 |
| 弱停顿（≥0.15s） | **−1.0** | 可以断 |
| 没停顿 | **+1.0** | 尽量别断 |
| 切在一个词内部（如 ス｜ポーツ） | **+30** | 压倒性：宁可这行宽一点也不能劈词 |
| 下一行从附属語开头（助詞/助動詞/接尾） | +4 / +6 | 那就是把一个「文節」切开了 |
| 上一行行尾是「いや/あの/でも」这类只会起句的词 | +6 | 它属于下一句 |
| 行尾不像句末 / 行首像句首 | 见 `_boundary_cost` | 句末标点、終助詞、助動詞结尾 = 奖励；行尾是格助詞・連体化の、行首是「という/って」= 罚 |
| 行时长 <0.35s / <0.6s | +3.0 / +1.0 | "闪一下"的一两个字碎行 |
| 行时长 >8s | +0.5×(超出秒数) | 一行太长读不完（**12 秒是硬上限**，但单个超长词要放行——拦了会让整条 DP 无解） |

显示时间（不是"猜"的，是骨架）：起点 = 这一行第一个词的起点 **− LEAD_IN(50ms)**；
终点 = 最后一个词的结束（`HOLD_AFTER=0`，**说完就消失**，用户明确不要 1 秒停留），
但至少显示 `MIN_SHOW=0.6s`（免得一闪而过），且不超过下一行的起点 −0.05s。

## 3. 第二遍补漏（`recover_missed`，2026-09-15 加）

**起因**：用户逐条人工审核一集，确认了 **25 处"有人在说话但没字幕"**。

**根因**：不是模型不行，是**第一遍的 VAD 把那段当静音滤掉了**（小声说话、压着 BGM 的说话、
短促应答最容易中招）。同一个窗口**关掉 `vad_filter`** 重听，Whisper 自己就听回来了，
文本质量还比另一个模型好——所以要改的是**切块方式**，不是换模型。

规则（对着那 25 处标注调出来的）：

| 规则 | 依据 |
|---|---|
| 候选窗口 = **字幕时间轴上的空档** ≥ `RECOVER_MIN_GAP`(0.8s) | 确认的漏句里最短的停顿就是 0.8s；04:19 那句跨 1.31s 停顿 + 0.26s 语音片（只看"VAD 静音"会漏掉它） |
| 长空档**切成 ≤ `RECOVER_MAX_WINDOW`(12s) 的小窗** | 13.4/15.6/16.9/31.5/54 秒的空档里都有真话；一次喂几十秒容易听成一坨 |
| 窗口 ±`RECOVER_NEAR_SPEECH`(3s) 内要和某段 VAD 语音有 ≥0.15s 重叠、音量 ≥ `RECOVER_SILENT_RMS`(0.004) | 排除"长时间没人说话"和真静音（关 VAD 的 Whisper 在纯音乐/咳嗽处会幻觉出整句） |
| 这一遍 `vad_filter=False`，**音频切片直接喂 numpy 数组** | 别用 `clip_timestamps`：那样每次调用都会重新解码整段音频，98 个窗口多花 3 分钟（实测 199s → **61s**） |
| 与已有字幕**时间重合 ≥60%** → 当作同一条（新文本更长就补成整句） | 用户指出"漏的是完整句子"（05:39 那条现有字幕只有后半截） |
| 与相邻字幕字符二元组重合 <50% 才算新句 | 排除"把隔壁那句的尾巴又听一遍" |
| 参照系必须是"进来时那份字幕"，不能拿边加边长的列表去比 | 实测这样新条会互相压制，召回 21/24 → **12/24** |

**效果**（拿人工标注当验收集，同一集）：该救回的 24 处**救回 21 处**；不该加的 6 处误加 5 处
（其中 2 处是 OP 歌词——用户要求 **OP 不做特殊处理**，跟正文一视同仁）；第二遍耗时 +51s/集。

**试过但否定的**：

- 用 Whisper 自己的置信度（`no_speech_prob` / `avg_logprob`）当幻觉闸门 → 真漏句本来就是
  小声/BGM 里，模型对它们同样没信心：召回 21/24 → **14/24**，误报只降 1（5→4）。**别用**。
- 给 OP/ED 开死区（VAD 连续 25s 无语音就整段跳过）→ 用户否掉："OP 不做特殊处理"。

## 4. 怎么验收（改算法必须跑）

断句对不对**只能靠耳朵**，所以流程是"人工标 → 打分 → 改 → 再打分"。打分工具在 `dev` 分支的
`qa/score`（用法见 `docs/reviewing.md`），口径**钉死**：

- **合并**标记 = 那个词缝上**不该**有切点；**拆分**标记 = **该**有切点；
- 允许**差一个词缝**（人点的是"这两句该分开"，落在相邻词缝上阅读体验一样）。

当前成绩（"不是哥们 E11"，80 条标记）：

| 指标 | 值 |
|---|---|
| 行数 | 310 |
| 不该断（合并）：通过 | 14 / 23 |
| 该断（拆分）：通过 | 30 / 57 |
| **合计** | **44 / 80 = 55%** |

**基线**：改之前是 0/80（那 80 条标记就是照着旧产物挑出来的）。改动过程中权重是用坐标搜索调的，
**搜索必须带"行数接近 311"的约束**——不约束的话它会往"疯狂断句"跑：606 行，分数更高但没法看。

## 5. 已知做不到的（别白费劲）

| 现象 | 原因 |
|---|---|
| 57 处"该断"里约 **30 处**改不动 | 那两句话之间**音频里一点停顿都没有**（同一口气说完），停顿+语法抓不到，纯语义问题 |
| 03:07 / 12:12 两处仍漏 | Whisper 关掉 VAD 也听不出来（另一个模型在同一窗口同样没给出可用内容）——要动得先做人声/BGM 分离 |
| 音乐/咳嗽处偶尔冒出幻觉句（如「ご視聴ありがとうございました」） | 关掉 VAD 的 Whisper 在"有能量但没人说话"的地方必然如此；目前靠"离 VAD 语音段的距离 + 音量"过滤，没有引入音乐判别 |

## 6. 参数速查

| 常量 | 值 | 作用 |
|---|---|---|
| `LINE_WIDTH_RATIO` | 0.80 | 单行最多占画面宽的比例（硬约束） |
| `PAUSE_CAND` / `PAUSE_STRONG` | 0.15 / 0.30 | 候选停顿 / 强停顿 |
| `SNAP_TOL` | 0.60 | 段边界离停顿多近才算同一个断点 |
| `LEAD_IN` / `HOLD_AFTER` / `MIN_SHOW` | 0.05 / 0.0 / 0.6 | 提前出现 / 说完停留 / 最短显示 |
| `INNER_PAUSE_MIN` / `INNER_PAUSE_STRONG` | 3.5 / 1.5 | 段内停顿当切点的门槛 |
| `VAD_PARAMS` | threshold 0.5、min_speech 100ms、max_speech 8s、min_silence 250ms、pad 50ms | 听写切块用的 VAD |
| `RECOVER_*` | 见第 3 节 | 第二遍补漏 |
| `W_*` / `PENALTY_*` / `*_DISCOUNT` | 见 `pipeline.py` 顶部 | DP 代价权重（**调之前先跑打分**） |
