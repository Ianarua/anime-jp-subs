# 模型选型记录

这份文档记录"为了把日语字幕做好，试过/评估过哪些模型，为什么用这个、为什么否掉那个"。

---

## 现在在用的

| 用途 | 模型 | 体积 | 许可 | 备注 |
|---|---|---|---|---|
| 日语听写 | faster-whisper large-v3（CTranslate2 / int8） | 3GB | whisper 系 | 一集 23 分钟约 **60s**（RTX 显卡）；没有 N 卡自动回退 CPU |
| 换气/停顿检测 | silero VAD（faster-whisper 自带） | 随包 | MIT | 不用额外装；参数 `min_silence 250ms / pad 50ms` 是调过的 |
| 日语分词/读音 | Janome | pip 依赖 | Apache-2.0 | 纯 Python、不用编译；送假名对齐靠它 |
| 字体度量 | Pillow | pip 依赖 | MIT-CMU | 逐字量宽度 + 读字体头算行高缩放 |
| 注音字体 | M PLUS 1 Code（`fonts/MPLUS1Code-VF.ttf`） | 1.6MB | OFL（可再分发） | 内附进 mkv，观众没装也能渲染 |

## 评估过、但否掉的

### kotoba-whisper-v2.0（日语微调，distil 版）——否

当初想用它，是因为日语专用、标点也许更好。

同集、同参数实测：

| 指标 | large-v3（在用） | kotoba-whisper-v2.0 |
|---|---|---|
| 整集听写耗时 | 60s | **16s（快 3.75×）** |
| 带标点的词 | 52 个（1.9%） | 23 个（**1.4%，更低**） |
| 词缝对齐停顿（中位误差） | **0.11s** | **1.23s（差 11 倍）** |
| 词缝落在停顿 ±0.15s 内 | 63% | **17%** |

它的卖点是速度，标点不是它承诺的能力；词级时间戳质量又掉了 11 倍——而断句正是建立在"词时间 + VAD 停顿"上的。结论：**换 ASR ≠ 提升断句**。

### SenseVoice（阿里 FunAudioLLM，非自回归）——否

当初想用它，是因为体积小、速度快、也许带标点。

| 指标 | 结果 |
|---|---|
| 日语 + `use_itn=True` 出标点 | ✅ 整集标点率 3.2%（Whisper 1.4%） |
| 逐字时间戳 | ✅ 有（和文本 1:1） |
| 整集耗时 | 44s |
| 接进断句 DP | ❌ token 是**单字**，而规则全按**词**设计——同一套 80 条标记：Whisper **35/80**，SenseVoice 只有 **25/80** |

### 单靠音高（F0）分辨说话人——否

当初想解决的是不装模型也能判断「换人了」。

切点两侧各取 0.7s 算自相关 F0 中位数：

| 组 | 音高差中位 |
|---|---|
| "不是同一个人说的"13 处 | **2.6 半音** |
| "应该并成一句的"对照组 | **2.0 半音** |

两个分布几乎重叠（同一句话内部的语调起伏能到 -14.5 半音）。结论：单靠音高分不出说话人，否掉。

## 评估过、留着备用

| 方案 | 体积 / 许可 | 能解决什么 | 代价 |
|---|---|---|---|
| XLM-R 标点恢复：`1-800-BAD-CODE/xlm-roberta_punctuation_fullstop_truecase` | 1.06GB（ONNX）/ Apache-2.0 / 非 gated | 给现有文本补「、。」——断句 DP 里"句末标点=强奖励"这条现在几乎没触发（整集只有 52/2749 个词带标点） | 需 `sentencepiece`；只做后处理、不动 ASR 和时间戳；日语专用的标点模型不存在（扫了 HF 上 283 个候选，只有这个支持日语，输出标签含日文全角 `。、？・`） |
| Demucs 人声/BGM 分离 | 模型 ~80MB，但要 torch | 03:07 / 12:12 两处 Whisper 关 VAD 也听不出来 → 先分离人声再听；动漫全程有 BGM | 要引 torch |
