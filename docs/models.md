# 模型选型记录（含被否掉的）

这份文档记录"为了把日语字幕做好，试过/评估过哪些模型，为什么用这个、为什么否掉那个"。
**每个结论都带实测数据**——以后想换模型时，先看这里有没有已经踩过的坑。

---

## 现在在用的

| 用途 | 模型 | 体积 | 许可 | 备注 |
|---|---|---|---|---|
| 日语听写 | **faster-whisper large-v3**（CTranslate2 / int8） | 3GB（用户自己下） | whisper 系（宽松） | 一集 23 分钟约 **60s**（RTX 显卡）；没有 N 卡自动回退 CPU |
| 换气/停顿检测 | **silero VAD**（faster-whisper 自带） | 随包 | MIT | 不用额外装；参数 `min_silence 250ms / pad 50ms` 是调过的 |
| 日语分词/读音 | **Janome** | pip 依赖 | Apache-2.0 | 纯 Python、不用编译；送假名对齐靠它 |
| 字体度量 | **Pillow** | pip 依赖 | MIT-CMU | 逐字量宽度 + 读字体头算行高缩放 |
| 注音字体 | **M PLUS 1 Code**（`fonts/MPLUS1Code-VF.ttf`） | 1.6MB | OFL（可再分发） | 内附进 mkv，观众没装也能渲染 |

## 评估过、但**否掉**的

### kotoba-whisper-v2.0（日语微调，distil 版）——否

**想解决的问题**：日语专用模型、也许标点更好。

**实测（同集、同参数）**：

| 指标 | large-v3（在用） | kotoba-whisper-v2.0 |
|---|---|---|
| 加载 / 词级时间戳 | 正常 | **原版直接崩**（0xC0000005 访问冲突） |
| 整集听写耗时 | 60s | **16s（快 3.75×）** |
| 带标点的词 | 52 个（1.9%） | 23 个（**1.4%，更低**） |
| 词缝对齐停顿（中位误差） | **0.11s** | **1.23s（差 11 倍）** |
| 词缝落在停顿 ±0.15s 内 | 63% | **17%** |

**崩溃根因（值得记）**：这个模型的 CT2 导出**把 `alignment_heads` 从 whisper-large-v3 抄了过来**
（索引到第 25 层），而它本身是 **distilled 模型、decoder 只有 2 层** → 词级对齐时 CT2 越界读内存。
定位手法：`python -X faulthandler`，栈顶是 `faster_whisper/transcribe.py:1709 → self.model.align(...)`。
修法（不动下载的原目录）：做一份硬链接副本、只改 config 里的对齐头（`[[1,0],[1,5],[0,0]]`）。

**为什么否**：我原以为它"日语专用、会输出标点"——**前提就是错的**：模型卡片写的是
**distilled（6.3× 加速）**，卖点是速度，压根没提标点；更致命的是词级时间戳质量掉了 11 倍，
而我们的断句恰恰建立在"词时间 + VAD 停顿"上。**教训：换 ASR ≠ 提升断句。**

### SenseVoice（阿里 FunAudioLLM，非自回归）——否

**想解决的问题**：体积小、速度快、也许带标点。

| 指标 | 结果 |
|---|---|
| 日语 + `use_itn=True` 出标点 | ✅ 整集标点率 3.2%（Whisper 1.4%） |
| 逐字时间戳 | ✅ 有（和文本 1:1） |
| 整集耗时 | 44s |
| 体积 / 许可 | 228MB（int8 ONNX）/ ⚠ `other`（FunASR MODEL_LICENSE，不是 Apache/MIT） |
| **接进我们的断句 DP** | ❌ **更差**：它的 token 是**单字**，而我们的规则（Janome 词性、文節、行宽）全按**词**设计——同一套 80 条标记：Whisper **35/80**，SenseVoice 只有 **25/80** |

**顺带一条有价值的发现**：把相邻 VAD 语音段合并成 20 秒的块喂给它时，它**跨过了 VAD 判定为
"静音"的那 10.7 秒**，把 Whisper 漏掉的那句听出来了（06:12「見て見てこれ」，正是人工审核标记的漏句）。
→ 由此定位到**漏句的根因是"第一遍的 VAD 把那段当静音滤掉了"，不是模型不行**；同一窗口关掉
`vad_filter`，Whisper 自己就听回来了，文本还更好。这就是 `recover_missed()`（第二遍补漏）的由来。

### 单靠音高（F0）分辨说话人——否

**想解决的问题**：能不能不装模型就判断"换人了"。

**实测**：切点两侧各取 0.7s 算自相关 F0 中位数——

| 组 | 音高差中位 |
|---|---|
| 用户标"不是同一个人说的" 13 处 | **2.6 半音** |
| 用户标"应该并成一句"的对照组 | **2.0 半音** |

两个分布几乎重叠（同一句话内部的语调起伏就有 -14.5 半音那种）。**结论：这条路直接否掉。**

### anime-whisper（litagin）——读不了

`litagin/anime-whisper` 是 Transformers 格式（`pytorch_model.bin`，756MB），
**faster-whisper 读不了**（要额外上 torch + transformers）；`litagin/anime-whisper-2` 直接 401。
CT2 转换版没找到。

## 评估过、**留着备用**的（还没做）

| 方案 | 体积 / 许可 | 能解决什么 | 代价 |
|---|---|---|---|
| **XLM-R 标点恢复**：`1-800-BAD-CODE/xlm-roberta_punctuation_fullstop_truecase` | **1.06GB（ONNX）/ Apache-2.0 / 非 gated** | 给**现有文本**补「、。」——我们 DP 里"句末标点=强奖励"这条现在几乎没触发（整集只有 52/2749 个词带标点） | 需 `sentencepiece`；只做后处理、不动 ASR 和时间戳；**日语专用的标点模型不存在**（扫了 HF 上 283 个候选，只有这个支持日语，输出标签含日文全角 `。、？・`） |
| **Demucs 人声/BGM 分离** | 模型 ~80MB，但要 torch | 03:07 / 12:12 两处 Whisper 关 VAD 也听不出来 → 先分离人声再听；动漫全程有 BGM | 要引 torch（+250MB 依赖）；每集多几分钟 |
| 换 ASR 提到"用户不用下 3GB"（SenseVoice 228MB） | — | 长远对开源项目有利 | 必须先解决"词级时间戳"这一关，否则断句会崩（kotoba/SenseVoice 都在这里翻车） |

## 换模型时的判断标准（总结）

1. **词级时间戳质量 > 一切**。我们的断句 = 词时间 + VAD 停顿；词时间一飘（中位 >0.3s），
   断句立刻崩。评估时先量"词缝 vs 真停顿"的偏移中位和 ±0.15s 命中率。
2. **token 粒度要跟下游匹配**。单字 token（SenseVoice）会让按词设计的语法规则失效。
3. **标点宁可后处理**。加在别的模型的转写上等于换了一套听写；加在**现有文本**上才有用。
4. 许可：开源仓库里只放能再分发的（Apache/MIT/OFL）；`other`（如 FunASR MODEL_LICENSE）要谨慎。
5. 体积/速度是次要项——先赢质量，再谈"让用户少下几个 G"。
